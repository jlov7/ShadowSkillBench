# Security policy

## Scope

The benchmark uses synthetic traces, policies, approvals, and identities. Do
not submit real personal, client, credential, or private-policy material in an
issue or pull request.

## Reporting a vulnerability

For a GitHub-hosted copy, open the repository's **Security** tab, choose
**Advisories**, then **Report a vulnerability**. The maintainer must enable
private vulnerability reporting before making the repository public. If that
button is unavailable, do not publish exploit details; open a detail-free issue
requesting a private security contact.

Include the affected path or component, a minimal reproduction using synthetic
data, impact, and the commit or package version. Remove secrets and personal
data from all reports.

Do not use the public issue tracker for active credential exposure, private-data
disclosure, or unpatched exploit details.

## Security boundaries

Local verification is not provider or production security validation. The
confirmatory protocol remains `HOLD` until its documented human anchor,
custody, execution, audit, and release gates pass.
